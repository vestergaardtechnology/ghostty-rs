# Porting Ghostty from Zig to Rust

This repository is a file-for-file port of [Ghostty](https://github.com/ghostty-org/ghostty)
(reference revision `93967b7f9478e94dcbb42125c8a90f34feb40d75`) from Zig to Rust.

The Zig reference checkout lives in `./ghostty` (git-ignored; clone it with
`git clone https://github.com/ghostty-org/ghostty.git ghostty && git -C ghostty checkout 93967b7f`).

## Layout

* `ghostty/src/**/*.zig` → `src/**/*.rs`, `ghostty/pkg/**/*.zig` → `pkg/**/*.rs`.
* File and directory names are converted to snake_case:
  `src/terminal/PageList.zig` → `src/terminal/page_list.rs`,
  `src/cli/ssh-cache/DiskCache.zig` → `src/cli/ssh_cache/disk_cache.rs`.
  `PORTING_STATUS.tsv` has the full mapping.
* The crate root is `src/root.rs`; the binary entry point is `src/main.rs`
  (port of `src/main.zig`).
* A Zig directory `foo/` becomes module `foo`. Its module file is the port of
  `foo.zig` (if it exists), else of `foo/main.zig`, else a generated `foo/mod.rs`.
  `renderer/OpenGL.zig`/`Metal.zig` are the module files for `renderer/opengl/`/`metal/`,
  `lib/TinyIo.zig` for `lib/tinyio/`.
* Module declarations are generated by `tools/scaffold.py` into a
  `// @generated-mods-begin ... // @generated-mods-end` block at the top of each
  module file. **Never edit that block by hand.** To gate a module on a platform
  or feature, put an inner attribute at the top of the *child* file, e.g.
  `#![cfg(target_os = "macos")]`.
* `src/build/` (the Zig build system) has no module counterpart; its job is done by
  `Cargo.toml` and `build.rs`.
* Rust module paths mirror Zig imports: `@import("../terminal/main.zig").Page` is
  `crate::terminal::Page` (re-export) or `crate::terminal::page::Page`.

## Status header

Each file starts with `//! Port of `src/...zig`.` followed by a status line:

* `//! STATUS: not yet ported.` – untouched stub.
* `//! STATUS: partial — <what is missing>` – some items ported.
* `//! STATUS: ported` – everything, including tests, ported.

Keep the original doc comments (`///`, `//!`) and meaningful inline comments.

## Translation rules

The port is **faithful**: same data structures, same algorithms, same names
(converted to Rust case), same tests. It is not a redesign. When the Zig code
does something for a reason (memory layout, performance, protocol compatibility),
keep it.

### Names

| Zig | Rust |
| --- | --- |
| file-struct `Foo.zig` (top-level fields) | module `foo` with `pub struct Foo` |
| nested decl `Foo.Bar` in `Foo.zig` | `foo::Bar` (module level, not nested) |
| `pub fn init(...)` / methods in `Foo.zig` | `impl Foo { pub fn init(...) }` |
| free `fn` in a lowercase (namespace) file | module-level `pub fn` |
| `camelCase` functions | `snake_case` |
| `snake_case` fields | unchanged |
| `pub const max_size = 10;` | `pub const MAX_SIZE: usize = 10;` |
| `enum { foo_bar }` | `enum { FooBar }` (if the Zig tag name is used as a string, e.g. config keys, provide `fn as_str()`/`FromStr` with the original spelling) |
| `union(enum)` | `enum` with data |
| `error{Foo, Bar}` | `#[derive(Debug, Clone, Copy, PartialEq, Eq)] pub enum XError { Foo, Bar }` + `Display` + `std::error::Error` |
| `?T` | `Option<T>` |
| `[]const u8` | `&[u8]` (use `&str` only when Zig guarantees UTF-8) |
| `std.ArrayListUnmanaged(T)` | `Vec<T>` |
| `std.AutoHashMapUnmanaged` / `StringHashMap` | `std::collections::HashMap` |
| `std.debug.assert(x)` | `debug_assert!(x)` |
| `unreachable` | `unreachable!()` |
| `a +% b` | `a.wrapping_add(b)` |
| `@intCast` / `@truncate` | `as` (or `try_from` when the Zig code relies on the check) |
| `std.log.scoped(.foo)` | `log::warn!(target: "foo", ...)` etc. |
| `comptime` generics | generics, const generics, `macro_rules!`, or `build.rs`-generated tables |
| `packed struct(uN)` | a struct with explicit bit packing (`to_bits`/`from_bits` or getters/setters on a `uN`) whenever the layout matters (hashing, C ABI, page memory, size assertions in tests); otherwise a plain struct |
| `extern struct` | `#[repr(C)] struct` |

Rust keyword module names use raw identifiers (`crate::lib::r#struct`).

### Memory

* Drop allocator parameters; use the global allocator (`Vec`, `Box`, `String`).
* Keep **semantic** allocation failures: structures with fixed capacity (e.g. page
  style/grapheme/hyperlink storage) return an `OutOfMemory`-style error that callers
  use to grow/split pages. Keep those as explicit error variants.
* Ghostty's page memory (`terminal/page.zig`, `bitmap_allocator`, `hash_map`,
  `ref_counted_set`, `size.Offset`) is a single contiguous buffer addressed by
  offsets. Port that design faithfully using raw pointers and `unsafe`; document
  invariants with `// SAFETY:` comments.
* `deinit` → `Drop` where ownership is simple; keep an explicit `deinit` only when
  the Zig API needs it (e.g. returning memory to a pool).

### Platform / build options

* `builtin.os.tag == .macos` → `cfg!(target_os = "macos")` / `#[cfg(...)]`.
* `terminal_options` (`src/terminal/build_options.zig`) and `build_config.zig` →
  Rust `const`s with the values of the **Ghostty application** build on the current
  target (Linux: GTK apprt, OpenGL renderer, fontconfig+freetype font backend;
  macOS: embedded apprt, Metal, CoreText). Use Cargo features only for optional
  heavyweight dependencies (`gtk`, ...).
* C libraries from `pkg/` (freetype, harfbuzz, fontconfig, oniguruma, opengl, ...)
  are ported as thin Rust wrappers in `pkg/` over `-sys` crates or hand-written FFI.

### Tests

* Every Zig `test "some name"` becomes `#[test] fn some_name()` inside
  `#[cfg(test)] mod tests { use super::*; ... }` at the bottom of the same file.
* Port **all** tests. Assertions must check the same things. Drop only the parts
  that test Zig-specific mechanics (allocator leak checks, `refAllDecls`,
  comptime-only checks); `@sizeOf`/`@bitSizeOf` assertions become
  `std::mem::size_of` checks when the size matters.
* Tests that can't run on Linux get the same `#[cfg]` as the code they test.
* Test data files under `ghostty/src/**/testdata` are copied to the mirrored
  location in `src/` and loaded with `include_bytes!`/`include_str!`.

### Workflow

* `cargo build` and `cargo test` must pass before committing.
* Commit messages: `port(<area>): <zig files> -> <rust files>`.
* Add dependencies to `Cargo.toml` in alphabetical order.
